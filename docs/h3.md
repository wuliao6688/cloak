# HTTP/3（QUIC）指南

## 概述

HTTP/3 是下一代 HTTP 协议，基于 QUIC（UDP）。截至 2026 年，Chrome / Firefox /
Safari / Edge 全部默认启用 H3，Cloudflare、Google、Akamai 等主流站点都支持。

**为什么爬虫必须支持 H3**：越来越多的 WAF 开始**只给 H3 连接放行**，或对
"声称是浏览器但没有 H3 能力"的客户端进行二次检测。

## cloak 的 H3 能力

| 能力 | 状态 |
|---|---|
| QUIC 连接（quic-go fork） | ✅ |
| **QUIC TLS 指纹（UQUICClient 注入浏览器 ClientHello）** | ✅ 独有 |
| H3 SETTINGS 指纹 | ✅ |
| H3 GREASE 帧 | ✅ |
| H3 Priority 参数 | ✅ |
| H3 伪头顺序 | ✅ |
| H2 vs H3 协议赛跑 | ✅ |
| 无 QUIC 自动降级 | ✅ |

> **与上游的差异**：其他实现（基于 fhttp + quic-go-utls 的方案）的 H3 只在应用层做了指纹
> （SETTINGS 帧），QUIC 内部的 TLS 握手仍是 Go 默认指纹——检测方看
> QUIC TLS ClientHello 就能识别。cloak 用 `UQUICClient` 把浏览器
> ClientHello 完整注入 QUIC TLS 层，是**唯一三层（TCP TLS + H2 + QUIC TLS）
> 全对齐**的实现。

## 快速使用

### 方式一：一行 API

```go
client := cloak.ImpersonateH3(profiles.Chrome_150)

resp, _ := client.Get("https://www.cloudflare.com/cdn-cgi/trace")
body, _ := io.ReadAll(resp.Body)
// 如果看到 http=http/3 说明成功走了 QUIC
```

### 方式二：链式

```go
client := cloak.ImpersonateChain(profiles.Chrome_150).
	EnableH3().
	Build()
```

### 方式三：底层

```go
// 纯 H3（不做 racing，只有 H3）
tr := cloak.NewH3Transport(profiles.Chrome_150)
resp, _ := tr.RoundTrip(req)

// H3 racing（推荐）
rt := cloak.NewH3RaceTransport(profiles.Chrome_150)
client := &http.Client{Transport: rt}
```

## H3 Racing 详解

```
首次请求 host  X
    │
    ├──▶ H3 连接（QUIC）─────────────────┐
    │                                   ├──▶ 谁先成功返回 → 缓存胜者
    └──▶ H2 连接（TCP，延迟 H2Delay）──┘         │
                                               ▼
                                    后续请求直接走缓存协议
                                     (h3 或 h2, 不再赛跑)
```

- **幂等方法才赛跑**（GET/HEAD/OPTIONS）——POST 等非幂等方法绝不并发发送
- 胜者按 `host:port` 缓存（`sync.Map`）
- H3 失败（UDP 被防火墙丢弃、服务器无 QUIC）→ 缓存为 h2，之后全走 H2
- H2 也失败 → H1.1 兜底（`Transport` 原有逻辑）

### RaceOptions

```go
type RaceOptions struct {
	Timeout time.Duration // 赛跑总超时（默认 10s）
	H2Delay time.Duration // H2 延迟启动（默认 0，立即并行）
}
```

## 指纹注入细节

### QUIC TLS 层（UQUICClient）

QUIC 的 TLS 握手与 TCP 的 TLS 不同：

1. ALPN 必须是 `h3`（TCP 画像的 ALPN 是 `h2` / `http/1.1`）
2. 只支持 TLS 1.3（TCP 画像含 TLS 1.2）
3. 必须携带 QUIC Transport Parameters 扩展（extension 57）

cloak 的 fork（`third_party/quic-go-utls`）在 `crypto_setup.go` 中：

```go
// 1. 取画像的浏览器 ClientHello Spec
spec, _ := clientHelloID.ToSpec()
// 2. 适配 QUIC：ALPN→h3、版本→TLS1.3、注入 QUIC TP 扩展
overrideALPN(&spec, []string{"h3"}, tpData)
// 3. HelloCustom + ApplyPreset：utls 不再用 ID 重新生成 Spec
uconn := tls.UQUICClient(&tls.QUICConfig{TLSConfig: tlsConf}, tls.HelloCustom)
uconn.ApplyPreset(&spec)
```

结果：QUIC TLS ClientHello 与浏览器逐字节一致（密码套件、扩展、GREASE、
顺序、TP 参数全保留），只是 ALPN 和版本按 QUIC 规范调整。

### H3 应用层

画像的 `http3*` 字段直接映射到 `http3.Transport`：

```go
AdditionalSettings        ← http3Settings + http3SettingsOrder
PriorityParam             ← http3PriorityParam
PseudoHeaderOrder         ← http3PseudoHeaderOrder
SendGreaseFrames          ← http3SendGreaseFrames
```

## 已知限制

| 限制 | 说明 |
|---|---|
| 外网 UDP 被代理拦截 | 部分网络环境（企业代理/透明代理）丢弃 UDP，H3 自动降级 H2 |
| 画像覆盖 | 47/77 画像有 H3 数据（Chrome/Firefox/Opera/Brave）；Safari 和移动端画像按论证不提供 H3（见 [画像体系](profiles.md)） |
| 0-RTT | 未启用（指纹安全优先） |
